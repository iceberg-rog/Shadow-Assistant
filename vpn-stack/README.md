# VPN stack (OpenVPN + L2TP/IPsec) with a unified quota panel

Adds **OpenVPN** and **L2TP/IPsec** to an Iran **relay**, alongside the existing
v2ray/xray customer service. Every VPN client egresses through the **same fleet
REALITY tunnel** to the foreign **exit**, so users connect to a fast domestic IP
but appear abroad.

One account (username + password) works on **both** OpenVPN and L2TP, with a
per-user **expiry date**, **traffic limit**, and **live usage** — all managed from
a single web panel.

## Architecture

```
client ──OpenVPN(1194/tcp)──┐
client ──L2TP/IPsec(500/4500/1701)──┤→ relay ──iptables REDIRECT──→ tcp2socks(:12345)
                                     │        (10.8.0.0/24 OpenVPN,      │
                                     │         10.10.0.0/24 L2TP)        ↓
                                     │                        xray-ovpn socks(:11080)
                                     │                                   │
                                     │                        fleet REALITY tunnel :9443
                                     ↓                                   ↓
                              (v2ray relay, untouched)              foreign EXIT ─→ internet
```

- **`tcp2socks.py`** — tiny transparent TCP→SOCKS forwarder (reads `SO_ORIGINAL_DST`).
  Used instead of xray dokodemo/TPROXY because some kernels reject `IP_TRANSPARENT`,
  and instead of redsocks (broken libevent on Ubuntu 26.04).
- **`ovpn-auth.py`** — OpenVPN `auth-user-pass-verify` script; validates against `users.json`
  (password, enabled, not expired, under quota).
- **`accounting.py`** — polls the OpenVPN status log + L2TP `ppp*` counters every 10s,
  adds per-user usage to `users.json`, and enforces expiry/quota (drops the user from
  `chap-secrets` and kills the live OpenVPN/L2TP session).
- **`panel.py`** — stdlib HTTPS panel: add/delete users (name, password, days, GB),
  toggle, reset usage, download the shared `.ovpn`, shows live usage + the L2TP PSK.

State lives in `/opt/ovpnpanel/users.json` (never commit — it holds passwords).

## Install (on the relay, after `installer/iran.sh`)

```bash
RELAY_IP=<relay public ip> EXIT_IP=<foreign exit ip> \
TUN_UUID=<tunnel uuid> TUN_PUB=<tunnel reality pubkey> TUN_SID=<tunnel short id> \
PANEL_USER=admin PANEL_PASS=<choose> L2TP_PSK=<choose> \
bash vpn-stack/install.sh
```

`TUN_UUID/PUB/SID` are the **same** values the relay's xray tunnel outbound uses
(they are generated by the exit). `PANEL_PASS`/`L2TP_PSK` auto-generate if omitted
and are printed at the end.

## When the exit changes (new foreign server)

The VPN stack egresses through the fleet tunnel, so when you move to a new exit you
only repoint the tunnel — the OpenVPN/L2TP/panel setup is untouched:

```bash
# on the relay: point xray-ovpn's tunnel outbound at the new exit
sed -i 's/OLD_EXIT/NEW_EXIT/; s/OLD_UUID/NEW_UUID/; s/OLD_PUB/NEW_PUB/; s/OLD_SID/NEW_SID/' \
    /usr/local/etc/xray/config-ovpn.json
systemctl restart xray-ovpn
# and update the REDSOCKS RETURN list + route-up if the exit IP is hardcoded there
```
(The customer xray relay's tunnel outbound is repointed the same way — see the fleet notes.)

## Client setup

- **OpenVPN:** download the single `fleet-ovpn.ovpn` from the panel → import in any
  OpenVPN app → it prompts for the **username + password** you created.
- **L2TP/IPsec:** phone → VPN → *L2TP/IPSec PSK* → server = relay IP, PSK from the panel,
  username + password from the panel.

> Note: in Iran, L2TP (UDP 500/4500) is heavily DPI-filtered and often blocked;
> OpenVPN is fingerprinted too. The v2ray (VLESS-REALITY/VMess) service is the most
> censorship-resistant. These are convenience options — test on the target network.
